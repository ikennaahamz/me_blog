Lesson 0001

Your Blog CRM Starting Map

In ten minutes, define the smallest CRM system that can support the blog without turning it into a software project.

The core idea

A CRM for this blog is not a sales dashboard. It is a memory system for people who raise their hand: subscribers, readers who reply, topic suggesters, project askers, and possible collaborators.

Official docs from HubSpot and Mailchimp both point to the same beginner pattern: capture contacts with a form, store useful fields, then organize contacts with tags or segments.

The first version

  1. Capture: add one homepage signup path, probably "monthly notes from what I learned and shipped."
  2. Store: collect email, optional name, source, interest, and consent status.
  3. Organize: tag by interest: ai, projects, learning-log, collaboration.
  4. Follow up: send a welcome email asking one question: "What topic made you subscribe?"
  5. Respect: include accurate sender information and a clear unsubscribe path for marketing email.

Choose the shape

Newsletter-first

Use Mailchimp, Kit, Beehiiv, or Buttondown. Best if the main relationship is publishing and replies.

CRM-first

Use HubSpot. Best if you want richer contact records, forms, and future project or client tracking.

Manual-first

Use a spreadsheet for the first 25 contacts. Best if you still need to learn what fields matter.

Practice: pick the first CRM fields

Write the five fields you would track for a new blog subscriber. Then check your answer.

Good starter answer

email, name, signup_source, interest, and consent_status. This is enough to personalize lightly, understand what writing attracts people, and avoid sloppy emailing.

Primary reading

Read HubSpot's guide to creating and embedding forms if you want CRM-first. Read Mailchimp's guide to getting started with your audience if you want newsletter-first.

For U.S. commercial email rules, review the FTC's CAN-SPAM compliance guide.
