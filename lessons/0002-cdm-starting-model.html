Lesson 0002

Your Blog CDM Starting Model

Build the first content data model for this blog without changing the site architecture yet.

The core idea

A CDM describes what your content is before deciding how it looks. For this blog, the model should answer: what is a post, what metadata does it need, how do posts connect to tags, and what does the homepage need to list them?

Start with four content types

Post

The main repeatable content: essays, project notes, learning logs, and field notes.

Tag

A controlled label for topics like ai, projects, learning, or web.

Author

One reusable identity for now: name, bio, email, and optional social links.

Asset

Images or downloads with alt text, caption, credit, and file path.

The first Post fields

  1. title: the display title.
  2. slug: the stable URL-friendly identifier.
  3. summary: one or two sentences for cards and metadata.
  4. publishedAt: the publication date.
  5. status: draft, published, or archived.
  6. type: essay, project note, learning log, or field note.
  7. tags: topic references.
  8. heroImage: optional asset reference.
  9. body: the actual Markdown content.

What this looks like in Markdown

---
title: "What I want this blog to remember"
slug: "what-i-want-this-blog-to-remember"
summary: "A first note on problems, questions, and useful references worth keeping in public."
publishedAt: "2026-06-19"
status: "draft"
type: "essay"
tags: ["learning", "projects"]
heroImage: "assets/editorial-desk.webp"
---

Post body goes here.

Practice: model one post

For the next thing you might publish, write a title, type, two tags, and summary.

Good starter answer

A strong answer separates the content's identity from how it appears on the homepage. If you can list a post card, build a tag page, and generate metadata from the fields, the model is doing useful work.
